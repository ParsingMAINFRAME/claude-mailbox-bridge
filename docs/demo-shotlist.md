# Public demo plan

Record a fresh disposable generic `worker` and `bot` setup. Use neutral local paths such as `$HOME/mailbox-demo` and a harmless instruction: “Reply with pong; do no other work.” This is a plan, not a recorded demo.

1. Show the one worker session ready with the exact release plugin enabled.
2. In a sender terminal, queue the instruction and highlight only its returned message ID.
3. Show queued → claimed → submitted → acknowledged → completed for that ID.
4. Show the two correlated reply states, then pause the worker and exit normally.
5. End on the repository URL and “Experimental — review session permissions.”

Record only disposable terminal content. Exclude usernames, home paths, account/email identifiers, auth screens, secret loopback URLs, environment values, real prompts, other windows and private project names. Keep the actual terminal steps and evidence honest: no synthetic state animation presented as a live run. The architecture graphic is a diagram, not an application screenshot.
